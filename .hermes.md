# Project context

## Clean-repository worker policy

- Coding workers must not receive the `browser` toolset. They may use `terminal`, `file`, and `skills`; production UI QA belongs to the parent orchestrator.
- `browser_console` is forbidden for this repository. The parent orchestrator must use accessibility snapshots/click/type/press for UI QA; coding workers may use inline `curl` or Python for API probes.
- Do not create diagnostic, temporary, probe, output, screenshot, or junk files in the repository. One-off checks must run in memory and write only to stdout.
- Before mutation, record HEAD, origin/main, tracked changes, untracked paths, and deleted paths. Re-check the same state before commit and after completion.
- Every task must declare an allowed tracked-path list. Modify only those paths. Prefer extending an existing test file; a new permanent test file requires a declared path and purpose in the task scope.
- If any unexpected path appears, stop before further mutation. Do not delete it. Report its exact path, contents/purpose, likely origin, and impact so the parent can obtain exact user approval.
- Before any file deletion, explain the file's purpose and obtain explicit approval for that exact path. Approval for one deletion does not apply to another.
- The coding worker performs code, tests, build, diff review, and Git delivery only. The parent orchestrator independently performs browser production QA after the worker reaches a terminal state.

## Collection loading invariants

- Cloudinary `public_id` is the stable identity for Collection cards; React keys and batch deduplication must not use an array index.
- Sort an arriving API batch deterministically, then append it after the existing sequence. Do not re-sort already rendered cards merely because another network batch arrived.
- A user-initiated sort change may re-sort the full Collection. Name, size, newest, and seeded-random ordering require `public_id` tie-breakers.
- Infinite scroll extends only the rendered prefix of the stable Collection sequence. Keep the square card media slot reserved so image decode and blur-up do not alter card geometry.
- Do not render Collection cards with CSS multi-column masonry: column balancing can move existing cards when items append. Use the stable grid for append-only loading.
- The Collection API cursor is the provider-loading authority; the client must walk bounded cursor pages until the requested UI page prefix exists. URL `page` is a navigation target, not an API offset.
- Keep provider total, loaded inventory, and filtered loaded matches as distinct counts. Mark Collection exhaustion only when the provider returns no next cursor; failed requests remain retryable.

## BANMAO AI browser-state invariants

- Structured AI `collection_results` live only in AI chat state. Collection deep links may locate a `public_id` by advancing bounded normal cursor pages, but must not reset or replace normal inventory, cursor, filters, sort, page, or in-flight loading state.

- The authoritative locale contracts are `banmao_language` and `banmao:language-change`; AI chrome supports `en`, `vi`, `zh`, `ko`, `ru`, and `id` reactively without rewriting historical message content.
- Chat bodies and session metadata live in native IndexedDB (`banmao-ai-chat`, schema version 1). Local storage is limited to small pointers, preferences, migration markers, and body-free cross-tab invalidations.
- Persisted content is capped transactionally at 500,000 deterministic UTF-8-byte estimated tokens per session. Reject projected over-cap writes without truncating existing history.
- Model request history is independently bounded to recent complete user/assistant turns; the persistence quota is not a model context-window claim.
