# Project context

## Collection loading invariants

- Cloudinary `public_id` is the stable identity for Collection cards; React keys and batch deduplication must not use an array index.
- Sort an arriving API batch deterministically, then append it after the existing sequence. Do not re-sort already rendered cards merely because another network batch arrived.
- A user-initiated sort change may re-sort the full Collection. Name, size, newest, and seeded-random ordering require `public_id` tie-breakers.
- Infinite scroll extends only the rendered prefix of the stable Collection sequence. Keep the square card media slot reserved so image decode and blur-up do not alter card geometry.
- Do not render Collection cards with CSS multi-column masonry: column balancing can move existing cards when items append. Use the stable grid for append-only loading.
